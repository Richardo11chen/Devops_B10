# e11e12-1 接口契约

|接口|请求/响应|状态码|
|---|---|---|
|POST /v1/jobs|`idempotency_key`、`input(mode/repo/base/target/candidate/fixed_report/expected_output/build_timeout/subdir)`；返回 `job_id`/`status`/`request_hash`|202，错误输入 400，幂等冲突 409|
|GET /v1/jobs/{job_id}|任务状态、`trace_id`、`error`|200，不存在 404|
|GET /v1/jobs/{job_id}/artifacts|阶段清单与 `artifact://` URI/SHA256|200，结果未生成 409|
|GET /v1/jobs/{job_id}/files/{相对路径}|产物文件与 `X-Content-SHA256`|200，不存在或越界 404|

任务状态：`QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`TIMED_OUT`。输出 envelope 的 `schema_version`、`job_id`、`trace_id`、`kind`、`commit`、`status`、`data`、`artifacts` 为消费者依据。

`artifact://job编号/相对路径` 由该任务文件接口解析。MD 消费需核对目标 commit 和内容哈希；基线与目标提交不同是正常的，必须记录两者。

## 本次实测

- 服务：`python3 run_e11e12.py serve --port 8082`；`GET /health` 返回 `{"status":"ok","schema_version":"e11e12-1"}`。
- 提交：`data/api-request.json`（`idempotency_key=e12-241880214`）→ 202，job_id `job-1c94661c9ae5448aad6797200b73e03e`。
- 轮询：`RUNNING` → `SUCCEEDED`，trace_id `trace-b7be57fb23234978a13de1aba2480415`。
- 产物：`GET artifacts` 返回五阶段 artifact URI/SHA；`candidate.patch` SHA256 `88074f66c291dcad1344c48f6a2b9ddd42d235d9d0415c85fb33310c5b7cb2af` 与 `X-Content-SHA256` 一致。
- 幂等：相同键和输入重复 POST 返回同一 job_id；相同键改 target 返回 `409 {"error":"IDEMPOTENCY_CONFLICT"}`。
- 失败消费保护：`check_envelope` 拒绝旧 commit/错误 schema/FAILED 上游；`load_artifact` 拒绝哈希不一致；路径越界和已有证据覆盖均被拒绝。
