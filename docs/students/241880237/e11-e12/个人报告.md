## E11 轨道集成

**接口形态**：上下游之间不共享内存或数据库，只通过「JSON envelope + artifact 文件」交接。envelope 固定字段 `schema_version / job_id / trace_id / kind / commit / status / data / artifacts`；`artifacts[]` 每项给 `uri`（`artifact://<job_id>/<相对路径>`）与 `sha256`。

**阶段与字段映射**：

| 阶段 | 输入 | 输出（data 内关键字段） |
|---|---|---|
| `draft` | repo + base/target + candidate.Dockerfile | `attempts[]`：`build_exit_code`、`failure_class`、`image_id` |
| `full-check` | base 提交快照 | `findings[]`：`type/target/dependency/evidence[]/declared_dependencies` |
| `incremental-check` | base→target 两次快照 | `findings[]`、`added[]`、`resolved[]`、`key` |
| `fixed-md` | 上游 MD 报告 | 规整后的 `findings`（去掉非 MISSING 项） |
| `repair` | fixed-md + 项目快照 | `candidate.patch`、`repair-plan.json`（每项 `target/dependency/style`） |
| `recheck` | 打补丁后的副本 | `findings[]`、`added[]`、`resolved[]` |

映射的关键点是 `findings[].target/dependency` 直接成为 `repair` 的编辑对象，`style`（`direct`/`macro`/`mixed`）由目标行是否含宏展开决定，而不是由报告指定。

**本人的代码修改**（`labs/e11e12/test_contract.py`，新增类 `Student241880237`，未改动 `Contracts` 与组长的 `Adaptation`）：
`test_two_missing_for_same_target_are_ordered_and_merged` —— 同一目标 `main.o` 同时缺 `config.h` 与 `extra.h` 时，断言计划两项、顺序固定为 `config.h` 再 `extra.h`、diff 只有一行 `+main.o:`。
构造时故意把 `#include "extra.h"` 放在 `#include "config.h"` 之前，`gcc -MM` 原始输出顺序因此是 `extra.h, config.h`；实现若照抄编译器顺序，顺序断言即失败。实际 `scan()` 按依赖名排序，故通过——证明顺序由依赖名稳定决定，与编译器输出顺序无关。
