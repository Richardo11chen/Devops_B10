# AI使用记录

工具/模型/日期：
AI 编程助手（WorkBuddy，底层模型 DeepSeek-V4.1-Flash），2026-11-03。

输入上下文与问题：
向助手提供 E8–E10 材料包、`labs/e8e10/lab.py` 与 `test_profile.py` 源码、E8 的实际运行日志，问题是：现有 7 项测试里哪些行为没被覆盖，选一个能守住「只修 MD、不动 RD」边界的新用例。

模型建议：
助手读代码后指出：`test_patch_preserves_redundant_dependency` 只覆盖「有 MD 时顺带保留 RD」，没有覆盖「报告只有 RD、无 MD」这一输入类别；并建议断言四点——空 diff、空 plan、Makefile 字节不变、`unused.h` 仍在声明中。
助手另外提出做变异测试，验证这条用例是否真的能发现错误实现。

采纳/拒绝及理由：
- 采纳「只有 RD 的报告不应产生任何动作」这个用例方向，理由：它对应论文「RD 只报告不修复」的边界，且是原测试集的空白。
- 采纳变异测试的做法，理由：仅「测试通过」不能说明测试有效。
- 一种变异（顺手删除 RD）被两条测试同时捕获，助手如实指出这**不构成**新测试的独占价值，并追加第二种变异（无 MISSING 时静默重写文件）才证明独占覆盖——这条判断被采纳。

人工修改：
- 选定方向为「只有 RD 的报告」；
- 确认断言集合（四条）与独立预期写法（先写预期再跑代码）；
- 核对 `patch()` 的 `STALE_REPORT` 与 `UNSUPPORTED_*` 分支确实存在，确认用例不会与既有分支冲突。

实际验证命令/输入/结果：
- `python3 -m unittest discover -s labs/e8e10 -p test_profile.py -v` → `Ran 8 tests ... OK`，退出 0。
- 变异 1（删 RD）：新测试与旧测试均失败。
- 变异 2（无 MISSING 时去掉末尾换行）：新测试失败、旧测试通过 → 新测试具备独占覆盖。

边界说明：
参考实现 `lab.py` 的算法逻辑**未由 AI 修改**；AI 的产出限于「读代码定位覆盖空白、给出用例骨架、生成变异验证脚本」。所有结论均以实际运行日志为准。
