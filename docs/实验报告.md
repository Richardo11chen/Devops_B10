## 故障与限制

### 环境故障（不是实验要观察的目标故障）

| 故障 | 现象 | 处理 | 影响面 |
| :--- | :--- | :--- | :--- |
| Docker Hub 直连不通 | `registry-1.docker.io` 无响应，`docker pull` 挂死 | 配 `/etc/docker/daemon.json` 的 `registry-mirrors` 指向 daocloud | 只影响拉取路径，镜像摘要不变 |
| `deb.debian.org` 极慢 | 实测 **7–32 KB/s**（多次采样 7.1 / 28.8 / 29.2 / 32.3 KB/s）；`build-essential` 需下 82.9 MB，一次冷构建 **1 小时 58 分** | 本机跑一个 HTTP 正向代理，把 `deb.debian.org` 请求按原路径转到 `mirrors.aliyun.com`（实测 851 KB/s），并在 `/root/.docker/config.json` 注入 `http_proxy` | 冷构建耗时降到 **172 秒** |
| `m.daocloud.io` 在 GitHub Runner 上不可用 | `unexpected media type application/octet-stream`、`TLS handshake timeout` | 把 `services/draft/Dockerfile` 两行 ARG 改回官方源（`python:3.13-slim@…` / `docker:28.5.1-cli@…`），本机由 daemon mirror 接管 | 一次无效的 CI 演示，已重做 |

**关于 apt 代理的说明（需明确交代）**：候选 Dockerfile **一个字节都没有改**，`candidate_sha256` 与 `provenance.json` 全部保持有效；代理只改变「从哪里取同一份 Debian 档案」，apt 仍然用 Debian 自带的 `InRelease` 签名校验包内容。这属于构建环境适配，不是对候选的修改。
